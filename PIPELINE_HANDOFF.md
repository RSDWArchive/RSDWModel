# RSDWModel Pipeline Handoff

This document is the orchestration contract for running RSDWModel from a larger
multi-project update pipeline. It is intentionally operational: use
`docs/Development.md` for deeper maintainer notes.

## Project Role

RSDWModel converts RuneScape Dragonwilds model data into static website assets
for [rsdwmodel.com](https://rsdwmodel.com/).

The pipeline consumes:

- Installed game files and UE4SS output.
- Shared Retoc legacy package output under `E:\Github\Retoc`.
- A current CUE4Parse source checkout under `E:\Github\CUE4Parse`.
- RSDWArchive exported metadata under `E:\Github\RSDWArchive\<version>\json`.

The pipeline produces:

- Extracted `.uemodel` source data under `<version>\`.
- Model inventories under `<version>\ModelData\`.
- Web glTF/bin/WebP assets under `<version>\WebAssets\`.
- Website search, avatar, equipment variant, and animation indexes under
  `website\`.
- Optional git commit batches sized for GitHub's normal file limits.

RSDWModel does not own the shared Retoc cache, the CUE4Parse checkout, or
RSDWArchive. A larger orchestrator should treat those as upstream dependencies.

## Upstream Order

Run or verify these stages before a full RSDWModel update:

1. The game is installed and updated.
2. UE4SS has generated the current `.usmap` and UHT header dump.
3. RSDWArchive is current for the same game version.
4. `E:\Github\CUE4Parse` exists and is compatible with the current `.usmap`.
5. `E:\Github\Retoc\RSDragonwilds\<version>` exists or can be generated by
   RSDWModel through `retoc to-legacy`.

For the current dataset, the version folder is `0.12.0.0`.

## Required Inputs

Default expected locations:

- RSDWModel repo: `E:\Github\RSDWModel`
- Game root:
  `F:\SteamLibrary\steamapps\common\RSDragonwilds`
- UE4SS output:
  `F:\SteamLibrary\steamapps\common\RSDragonwilds\RSDragonwilds\Binaries\Win64\ue4ss`
- Retoc base: `E:\Github\Retoc`
- CUE4Parse source: `E:\Github\CUE4Parse`
- RSDWArchive version root: `E:\Github\RSDWArchive\<version>`

`tools\UpdateGameData.py` can override these with `--game-root`,
`--retoc-base`, `--cue4parse-root`, `--archive-root`, `--archive-json-root`,
`--usmap`, and `--version`.

## Orchestration Commands

Run commands from `E:\Github\RSDWModel`.

Preview the full pipeline without changing data:

```powershell
python tools\UpdateGameData.py --dry-run --web-assets full --web-animations full --equipment-variants full --glb none
```

Run a full build and write a git commit plan without committing or pushing:

```powershell
python tools\UpdateGameData.py --web-assets full --web-asset-workers 8 --web-animations full --equipment-variants full --glb none --run-git-plan
```

Run a full build, create planned commit batches, and push each batch:

```powershell
python tools\UpdateGameData.py --web-assets full --web-asset-workers 8 --web-animations full --equipment-variants full --glb none --git-commit-batches --git-push-each
```

For a repo state that is already fully built, skip rebuild stages and only plan,
commit, and push current changes:

```powershell
python tools\UpdateGameData.py --skip-retoc --skip-extract --skip-inventory --web-assets none --glb none --git-commit-batches --git-push-each
```

## Success Artifacts

A successful full update should refresh or validate these files:

- `<version>\PipelineRun.json`
- `<version>\CueExtractManifest.json`
- `<version>\ModelData\SM_Data.json`
- `<version>\ModelData\SK_Data.json`
- `<version>\WebAssets\WebAssetManifest.json`
- `<version>\WebAssets\WebAssetSizeReport.json`
- `website\model-index.json`
- `website\avatar-index.json`
- `website\equipment-variants.json`
- `website\animation-index.json`

Current measured generated WebAssets:

- Total: about `1.9 GiB`
- Exact bytes: `1,985,899,149`
- Equipment variants included: yes
- Web animations included: yes
- Files over `50 MiB`: none
- Files over `100 MiB`: none
- Published animation totals: `2,239` successful animations across `36` model
  groups, with `1,681` unsupported clips omitted from the website index.

## Success Checks

After a full build:

1. Check that `PipelineRun.json` exists for the version.
2. Check `WebAssetSizeReport.json` and fail the orchestration if any generated
   file is over GitHub's `100 MiB` hard limit.
3. Confirm `website\model-index.json`, `website\avatar-index.json`,
   `website\equipment-variants.json`, and `website\animation-index.json` exist.
4. If committing and pushing, confirm `git status --short` is clean afterward.
5. Confirm [rsdwmodel.com](https://rsdwmodel.com/) loads the current
   cache-busted website JavaScript and current website indexes after GitHub
   Pages deploys.

## Acceptable Partial States

- Unsupported animation compression is acceptable when recorded as
  `unsupported` during the run and omitted from `website\animation-index.json`.
- Overall WebAssets size can be large. The hard GitHub concern is the `100 MiB`
  per-file limit, not the total generated corpus size.
- GitHub Pages deploys only `website\`. Model payloads load from raw GitHub
  URLs under `<version>\WebAssets\`.
- If a very large data push does not trigger a Pages deployment because of
  workflow path filtering, make a small website-only cache-buster commit and
  push it.

## Failure Handling

Treat these as blocking orchestration failures:

- Missing game root, UE4SS header dump, `.usmap`, Retoc executable, CUE4Parse
  checkout, or required RSDWArchive JSON.
- Retoc cache conflict with a different game/version manifest.
- Non-empty incomplete Retoc cache unless the operator explicitly chooses
  `--force-retoc`.
- Any generated file over `100 MiB`.
- Failed git commit or push when `--git-commit-batches` / `--git-push-each` are
  requested.

Useful retry behavior:

- Retoc is skipped when the cache is already populated.
- CUE extraction resumes by skipping existing `.uemodel` outputs.
- Web asset and animation builders skip existing successful outputs unless
  forced.
- Animation packages known to have unsupported compression are cached during a
  run so the same unsupported package is not retried repeatedly.

## Downstream Contract

Static consumers should read website indexes from the Pages artifact and model
payloads from raw GitHub under:

```text
https://raw.githubusercontent.com/RSDWArchive/RSDWModel/main/<version>/WebAssets
```

The website's configured production domain is `rsdwmodel.com`, with
`website\CNAME` containing `rsdwmodel.com`.

Generated model assets are glTF-compatible approximations of Unreal materials.
The pipeline bakes known material, avatar color, held equipment, equipment
variant, and animation data into static web outputs, but it does not promise
full Unreal shader parity.
